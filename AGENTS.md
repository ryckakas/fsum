# fsum: agent rules

A zero-dependency Go library that returns the exact sum of float64 values, rounded once to the nearest float64. It
follows JavaScript's `Math.sumPrecise` semantics. `README.md` has the why. The approved plan, with its decision log
and research evidence, lives in `.plans/` (local only).

## Hard rules (non-negotiable)

- **Plan first for behaviour changes.** Anything that can change a returned value, the public API or the documented
  guarantees needs an approved plan before code (use the planning skill; plans live in `.plans/`, gitignored).
  Small, well-scoped changes (a CI gate, a Makefile target, docs) go straight to implementation.
- **Work lands through pull requests.** Never push to `main`; the ruleset rejects it anyway.
- **Zero dependencies.** go.mod has no `require` lines. Benchmarks compare against inline reimplementations, never
  an imported library.
- **The `go` line in go.mod is the floor for every importer.** Raise it only when a newer language or library
  feature is actually used. The `toolchain` line is the single place to raise the Go used for development and CI.

## Documented guarantees

These are the product. A change that weakens one is a breaking change, whatever the diff looks like.

1. Never panics, for any float64 input.
2. The result does not depend on input order.
3. The result is bit-identical to what the `Math.sumPrecise` specification requires, except that a NaN result is
   always `math.NaN()`. The specification is the oracle, not any one engine: engines return NaN in a corner (more
   than 2^45 values with a huge running total) where the exact sum is finite.

Each one has a test that fails when it breaks. Keep it that way.

## Gates

Run `make check` before considering a change done; green there should mean green in CI. It runs golangci-lint,
bonsai-lint, the go mod tidy drift check, zizmor (offline), gitleaks over the whole git history,
actionlint (with shellcheck), typos, race tests on the pinned toolchain, plain tests on the floor Go, govulncheck
and `go vet`. Before a release, `make fuzz` (10 minutes per fuzz target by default) must find nothing.

- Never report a gate as green that you did not actually run. Fix violations in the same change; flag
  pre-existing ones instead of silently widening a change.
- CI pins every tool version exactly. Dependabot moves the actions. These are bumped by hand: the golangci-lint
  version (`ci.yml` and Makefile), the bonsai-lint, govulncheck and actionlint versions (Makefile), the
  zizmor image digest (`ci.yml`), the gitleaks image (Makefile) and the ShellCheck version and SHA-256 (`ci.yml`).
- Every `uses:` is pinned to a full commit SHA with its version in a comment. Workflows default to
  `permissions: contents: read`, with `persist-credentials: false` on every checkout.
- bonsai-lint gates cognitive complexity at 15 with no baseline. Restructure rather than suppress.
- `//nolint` must name the linter and give a reason (`//nolint:gosec // <why>`). A bare one fails lint.

## Comments

Don't comment. The exception is a short "why" (rationale, a trade-off, a floating-point subtlety that the code
cannot show), and only where it is genuinely needed. Three lines is the ceiling; one is usually right. Never
restate what the code already says.

No em dashes (or en dashes used as dashes) in docs, the README or comments. Use a colon, a comma, parentheses or
two sentences instead.

**Licence headers are an exception too.** A file translated from third-party code keeps that code's copyright
and licence notice in a header comment, separated from the `package` line by a blank line.

**API docs are the other exception.** Every exported identifier has a doc comment; revive enforces it. The first
sentence says what the item is, starting with its name. The rest adds only what the signature can't say.

## Testing conventions

- Expected values come from two independent oracles: the committed golden corpus (`testdata/golden.txt`,
  generated by `scripts/gen_golden.py` with exact rational arithmetic and cross-checked against V8 by
  `scripts/crosscheck.mjs`) and an in-process `math/big` sum. Never hand-compute an expected float.
- Test inputs live in variables or slices. A constant expression such as `1e308 + 1e308 - 1e308` is folded
  exactly at compile time and tests nothing. Write negative zero as `math.Copysign(0, -1)`: the constant `-0.0`
  is +0.
- Compare results by bits (`math.Float64bits`), except NaN, which is compared with `math.IsNaN`.
